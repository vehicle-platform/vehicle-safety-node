# CubeMX project image: safety-node, NUCLEO-G474RE

**UNVERIFIED ON HARDWARE. The boards are not yet on the desk.** Nothing in this folder has been run on a target. It compiles (Debug, `arm-none-eabi-gcc`), nothing more.

Generated by STM32CubeMX 6.18.0 with STM32Cube FW package FW_G4 V1.6.3 (installed package 1.6.0 with patch 1.6.3). Target: STM32G474RET6 (Cortex-M4F) on the NUCLEO-G474RE.

This project is the pin-plan image from `vehicle-defs/docs/g474-pin-plan.md` (D-118, roadmap T6). It is **not wired to the platform yet**: the `features/`, `services/` and `hal/` layers of this repo do not call into it, and the root CMake build does not include it. Wiring the generated init code behind the `hal/` layer is T13.

Rules:

- The generated code is edited only inside `USER CODE BEGIN` / `USER CODE END` blocks (see `CLAUDE.md`). Everything else is overwritten on regeneration.
- Change the configuration in `safety-node.ioc` (CubeMX), then regenerate. Do not hand-edit generated files.
- This is red-zone, invariant-8 code (clock, reset, MPU, linker script): run `safety-reviewer` after any change.

## Regenerate

1. Install STM32CubeMX 6.18.0 and the STM32Cube FW_G4 V1.6.3 package.
2. Open `cubemx/safety-node.ioc` in CubeMX and press *Generate Code* (toolchain CMake, library files copied only as needed).
3. Or headless, from a script file `gen.txt` (the first line is required):

```
popupwrapper set
config load <repo>/cubemx/safety-node.ioc
project name safety-node
project path <output dir>
project toolchain CMake
project generate
exit
```

Run it with `STM32CubeMX -q gen.txt`. Build with `cmake --preset Debug && cmake --build --preset Debug` inside the generated `safety-node/` folder.

Loading the `.ioc` logs CubeMX messages that cannot be removed: one `Pin<N> (VP_RIF_VS_RIF1) cannot be retrieved for this MCU` and a series of `IP (DMA) : Parameter (...) has Id (...) currently not set`. CubeMX prints them when it reloads a file it saved itself; the DMA configuration is read correctly and appears in the generated code.

## SPI2 (own MPU-6500 IMU, plan: PB13 SCK, PB14 MISO, PB15 MOSI, AF5)

Full-duplex master, 8-bit, MSB first, mode 3 (CPOL high, CPHA second edge), software NSS, baud rate prescaler 256 (170 MHz / 256 = 664 kHz, within the 1 MHz MPU-6500 register-access limit). Sensor-data reads of up to 20 MHz are a later optimisation. The chip select is the plan's `CS_IMU_SAFETY` on PB12, a GPIO output initialised high (idle high). The interrupt input is PA8.

The CubeMX board support package (BSP COMMON) is removed from the project because it reserves LPUART1, which the plan uses for the ST-LINK virtual COM port (PA2/PA3).

## Open

- DMA channel allocation (TIM3_CH1 and TIM3_CH2 on DMA1 channels 1 and 2) is a proposal; the plan says to verify it in CubeMX.
- Timer periods (LED ring), I2C timing, UART baud rates and every other parameter not named in this file: CubeMX defaults.
- The linker script and the clock/reset/option-byte init are CubeMX defaults (red zone: need a `safety-reviewer` pass before they are final).
- The generated linker script still reserves a heap region (`_Min_Heap_Size 0x200`, `STM32G474xx_FLASH.ld:66`, reserved at `:235`); no code uses it any more (`_sbrk` always fails, below), but the 512 bytes stay reserved until the linker script is reviewed (T13). Invariant 5 forbids dynamic memory on this MCU.
- Option bytes are not set by the image: nSWBOOT0/nBOOT0, `BOR_LEV` and `IWDG_SW` are at their factory values until the first-flash command below is run.

## Pre-power-on hardening (T6b, 2026-11-27)

The design choices below are PROVISIONAL under D-134 item 3 (optimise later).

### FDCAN1 (platform bus)

Classic CAN, no BRS, `FDCAN_MODE_NORMAL`. Nominal 500 kbit/s from the 170 MHz PCLK1 kernel clock: prescaler 20 (8.5 MHz, 117.6 ns tq), sync jump width 2, time segment 1 = 14, time segment 2 = 2, so 1 + 14 + 2 = 17 tq per bit, sample point 15/17 = 88.2 %. Generated: `Src/main.c:211-214`. `StdFiltersNbr = 4` (`Src/main.c:223`): three safety IDs (0x020, 0x022, 0x081) in RX FIFO 0 and 0x120 in RX FIFO 1, per `src/hal/can.h`. The G474 HAL has a fixed message RAM (3 RX FIFO 0 elements, 3 RX FIFO 1 elements, 3 TX elements), so the FIFO depths are not configurable here. The filter elements themselves, the global filter (reject every non-matching standard frame, reject remote frames, reject extended frames, FD operation off), FIFO blocking mode and the boot self-check are code, not CubeMX configuration: T13 (`hal/can`). No FDCAN interrupt is enabled yet.

### IWDG

LSI 32 kHz (started in `SystemClock_Config`, `Src/main.c:161`), prescaler /32 (1 kHz tick), reload 99 (`Src/main.c:296-298`): **timeout about 100 ms, PROPOSED** (nothing in `CLAUDE.md`, the pin plan or DECISIONS fixes a value; D-118 item 5 only requires an independent watchdog). The LSI tolerance (RM0440 / datasheet: roughly 29.5 to 34 kHz) moves it to about 94 to 108 ms. Window disabled (4095). It is refreshed once per super-loop iteration in `main`'s USER CODE (`Src/main.c:135`); the loop is a placeholder until T13, and **the watchdog/heartbeat module owns the refresh from T13**, after the decision steps. The loop must therefore finish in well under 100 ms, and the init after `MX_IWDG_Init` up to the first refresh must too. With a debugger halted the IWDG keeps counting (the freeze bit `DBG_IWDG_STOP` is not set), so breakpoints reset the MCU unless it is set while debugging. It is started by the option byte `IWDG_SW = 0` (below) before any code runs and again by `HAL_IWDG_Init`.

### Error_Handler

IRQs off, then `safety_outputs_off()` (USER CODE 4 in `Src/main.c`, declared in `Inc/main.h`): the GPIO clocks are enabled and every actuator output is driven low through BSRR (direct registers, independent of `MX_GPIO_Init`); then `NVIC_SystemReset()`, no spin. The same `safety_outputs_off()` runs first in the NMI, HardFault, MemManage, BusFault and UsageFault handlers (`Src/stm32g4xx_it.c`), which then spin until the IWDG resets the MCU. **A reset does not mean "unlocked":** the latching immobilizer relay keeps a LOCKED latch through a reset, and a SET pulse cut short can leave it in an unknown state (D-097); the boot handling of that state is T13 (below). Final set (labels from `g474-pin-plan.md` section 3):

| Pin | Label | Why |
|---|---|---|
| PC4 | `IMMO_SET` | relay coil pulse, must never stay energised (invariant 6) |
| PC5 | `IMMO_RESET` | relay coil pulse, same |
| PC2 | `DEADMAN_KICK` | low stops the retrigger, so the external dead-man drops the ring supply (D-072 item 5) |
| PB0 | mirror LED left | "side clear" is never a static output |
| PB1 | mirror LED right | same |
| PA5 | status LED LD2 | not safety relevant, driven low for a defined state |

PB12 (`CS_IMU_SAFETY`) is deliberately left alone (chip select, idle high, not an actuator). PC6/PC7 (LED ring data, TIM3 AF) are not touched: the ring is made safe by the dead-man supply cut, and the reset stops the timer.

| IRQ | Priority | Note |
|---|---|---|

| FDCAN1 | not enabled yet | T13 must give it a number below 5 (proposal 1) |
| Schedule timer | not present yet | T13 must give it a number below 5 (proposal 2) |

### RTC and LSE

Unchanged: the pin plan does not need the RTC now. The LSE is never started (the LSI is started for the IWDG only).

### First flash: option bytes (cannot be set without hardware)

Run once on every new board, with the board connected over SWD:

```
STM32_Programmer_CLI -c port=SWD -ob nSWBOOT0=0 nBOOT0=1 BOR_LEV=4 IWDG_SW=0 NRST_MODE=3
```

| Option | Value | Why |
|---|---|---|
| `nSWBOOT0` = 0 | boot source taken from the `nBOOT0` bit, not the BOOT0 pin | a stray level on PB8 (BOOT0 pin) at reset cannot enter the system bootloader |
| `nBOOT0` = 1 | boot from main flash | with nSWBOOT0 = 0 this selects flash |
| `BOR_LEV` = 4 | brownout reset at the highest threshold (nominal 2.8 V falling) | a cold crank dip of the 3.3 V rail at 170 MHz resets the MCU cleanly instead of running with a corrupt state; the node boots unlocked |
| `NRST_MODE` = 3 | NRST pin bidirectional (the factory default) | an internal reset (IWDG, software, BOR) drives the NRST pin, so the external dead-man and the other nodes see it; the reset-cause decode relies on PINRSTF being set on every reset |
| `IWDG_SW` = 0 | hardware watchdog: the IWDG starts at reset | it runs even if the software never reaches `MX_IWDG_Init`, and software cannot stop it |

CONFIRM before the first use: the option names as spelled by the installed STM32CubeProgrammer (`-ob displ` lists them) and the `BOR_LEV` code to voltage mapping (RM0440 FLASH_OPTR; the header `stm32g474xx.h:5241-5245` defines the codes 0 to 4, the voltages are quoted from memory, the reference manual was not available locally). Check the result with `-ob displ`.

## Must fix before first power-on (safety review 2026-11-27)

- [x] IWDG: enabled, LSI /32, reload 99, about 100 ms, refreshed once per loop iteration (`Src/main.c:296-298`, `:135`). The hardware start by `IWDG_SW = 0` is the first-flash command above (open until run on the board). The refresh moves to the watchdog/heartbeat module in T13.
- [x] `Error_Handler` drives PC4, PC5, PC2, PB0, PB1 (and PA5) low, then `NVIC_SystemReset()` (`Src/main.c:651`). Not yet tested on a target (a fault injection test belongs to T13).
- [ ] Option bytes: command written above, not yet applied (needs the board). Open until the first flash.
- [~] FDCAN1: bit timing 500 kbit/s and `StdFiltersNbr = 4` done (`Src/main.c:211-219`). Still open for T13: the filter elements, the global filter that rejects non-matching, remote and FD frames (not expressible in CubeMX), FIFO blocking mode, interrupts, and the boot self-check.
- [x] FDCAN1 automatic retransmission on (`Src/main.c:208`, `.ioc`): a 0x023 or 0x082 frame that loses arbitration is resent instead of dropped.
- [ ] CAN TX with retransmission on (safety review 2026-11-27): with no other node acknowledging, a frame is retried forever; T13 handles a full TX FIFO without blocking and drops stale queued frames instead of resending old alive counters.
- [x] LED-ring DMA IRQs at priority 5, below SysTick (0); FDCAN and the schedule timer must be given a number below 5 when they are enabled (table above).
- [x] `_sbrk` always fails and a CI `nm` gate rejects every heap symbol (T77): `User/sbrk_fail.c`, `sysmem.c` dropped from the target in `CMakeLists.txt:40-45`, gate `tools/check_image_heap.py` run (Debug and Release, with a `malloc` canary that must fail) by the `renode-boot` job step "Image gates (heap, fault handlers; Debug and Release)" in `.github/workflows/ci.yml`. The heap reservation in the linker script is the open item above.
- [x] Boot check of IWDG, option bytes and BOR level (T77): `boot_hw_config_check()` (`User/boot_checks.c:132`) compares `FLASH->OPTR` (nSWBOOT0, nBOOT0, BOR_LEV, IWDG_SW, NRST_MODE = 3) and `IWDG->PR/RLR/WINR` with the values of this README through the pure `src/hal/hw_config.h` (host test `tests/host/test_hw_config.c`). It is called after `MX_IWDG_Init` (`Src/main.c:125`) and only **records** a mismatch (`boot_hw_config_flags()`, bit mask `HW_CONFIG_BAD_*`); it never halts, because the option bytes are not applied before the first flash (the flag will read non-zero on every unflashed board). **T13, before the first ride:** the mask must be reported (0x082 / diagnostics) and acted on (halt or degrade), otherwise a board with the wrong BOR level or a software-started IWDG rides unnoticed.
- [ ] Immobilizer state at boot (safety review 2026-11-27, D-097): after any reset the relay state is unknown (LOCKED survives a reset, a truncated SET pulse is undefined): treat it as unknown and start the 10 s unlock timer; a boot never pulses the relay (repo `CLAUDE.md` rule 5; a RESET pulse at boot would change that rule and needs the user's decision). T13 (`features/immobilizer`).
- [~] Reset cause (safety review 2026-11-27). Done (T77): `RCC->CSR` is read first in `main` (`Src/main.c:93`, `User/boot_checks.c:90`) and cleared with `RMVF` (written back to 0 explicitly, RM0440 does not say it self-clears), decoded by the pure `src/hal/reset_cause.h`. The decode follows the real flag combinations (PINRSTF is set on every reset, BORRSTF also on power-on): priority IWDG > WWDG > LPWR > SFT > BOR > OBL > PIN-only (BOR before OBL until target measurements show what a power-on sets), host-tested with realistic combinations. Abnormal resets are counted in `.noinit` RAM (`boot_abnormal_reset_count()`) with a magic word and an inverted copy, so cold-boot garbage restarts at 0: IWDG, WWDG, illegal low-power entry and a software reset that left a valid fault record (the fault and `Error_Handler` paths, so an HSE-timeout or fault reset loop counts) increment (saturating); power-on/BOR and NRST-pin-only clear; a deliberate software reset, option-byte load and unknown leave the count. `boot_should_safe_halt(count, limit)` is the tested policy predicate (`tests/host/test_reset_cause.c`). **Open for T13:** (a) the halt itself (outputs off, no relay pulse; it touches the immobilizer start state, D-097) and the limit N; (b) `boot_abnormal_reset_count_clear()` after a healthy run; (c) reporting in 0x082: `HeartbeatSafety` in vehicle-defs has only SAFETY_NODE_MODE, SAFETY_ERROR_COUNT and SAFETY_UPTIME, so a reset-cause / reset-count signal needs a defs change first (defs follow-up, not made here). The `.noinit` section is an orphan section (the generated linker script has no USER CODE block): both objects (counter, fault record) are declared NOBITS and placed by the linker after `.bss`. Guards: CI `tools/check_noinit.py` (on the linked ELF: NOBITS, start at or above `_ebss`, end at or below `_sstack`) and `boot_noinit_placement_ok()` (`User/boot_checks.c:77`) at run time, which checks both objects against the same two symbols and otherwise skips the counter and the record. A regenerated linker script that lists `.noinit` explicitly is fine too.
- [ ] Watchdog refresh only after a flow-check token proves every step of the loop ran (consider the window); bound every I2C/SPI timeout (no `HAL_MAX_DELAY`; the PN532 init must fit in the 100 ms budget). T13.
- [x] The fault path does not push onto a possibly corrupt stack (T77): NMI, HardFault, MemManage, BusFault and UsageFault are naked (`Src/stm32g4xx_it.c:51-55`, bodies use `BOOT_FAULT_ENTRY()`, basic asm with a literal tag), reload MSP from `_estack` and branch to `boot_fault_safe_state()` (`User/boot_checks.c:57`), which inlines the always_inline `boot_safe_state()` / `boot_outputs_off()` (`User/boot_checks.h`): outputs off, then `SYSRESETREQ`. `Error_Handler` uses the same inline (`Src/main.c:684`); `safety_outputs_off()` stays as a thin wrapper. Before the reset the path stores a fault record in `.noinit` (`src/hal/fault_record.h`: tag of the path, CFSR, HFSR, RCC CIFR with CSSF, magic and check word, plain stores, no call); the next boot copies it (`boot_fault_record_get()`) and clears it so one fault counts once (reporting is T13, no CAN field exists in defs yet). CI (`tools/check_fault_handlers.py`, Debug and Release) fails unless each handler starts with the `_estack` load and `msr MSP` and has no push or call. Not yet run on a target.
- [~] FDCAN pre-start check (T77): `boot_fdcan_start()` reads the kernel clock (RCC, divided by the `FDCAN_CKDIV` PDIV field, `can_timing_kernel_hz()`) and the `NBTP` read-back and compares with 500 kbit/s (`User/boot_checks.c:160`, pure `src/hal/can_timing.h`, `tests/host/test_can_timing.c`, PDIV 0, 1 and 15 tested). **A failed check does not reset the node:** the controller stays stopped, `boot_can_fault()` reads true and the rt-core inputs stay invalid (nothing is received), so the D-042 own-IMU fallback and the blind spot keep running; a reset loop would take the safety function down for a bus fault. It is called in `main` under `#if defined(SAFETY_BOOT_START_FDCAN)` (`Src/main.c:126-134`), which no build defines: nothing starts FDCAN in this image, and Renode's M_CAN model does not store NBTP. T13 defines the macro when it wires `hal/can` and reports `boot_can_fault()`. vehicle-defs `gen/c/safety` has no platform-bus bit-rate constant (defs follow-up), so `BOOT_FDCAN1_EXPECTED_BPS` is a local 500000 (D-009).
- CI guards added with T77 (`renode-boot` job, checkout with recursive submodules): heap gate on Debug and Release plus a canary (a `malloc` ELF must fail the gate), fault-handler disassembly gate, `.noinit` placement gate, MISRA scan of the hand-written `cubemx/User/` files (deviations DEV-004 to DEV-006 in `misra/README.md`, inline suppressions only for 11.4/12.2/17.3/20.10).
- HIL (T26): the WS2812 LED ring keeps its last frame through a reset; it is blanked only by the 74HC123 dead-man (PC2 `DEADMAN_KICK` low), not by any code in the fault path. Verify on the bench that a HardFault and an IWDG reset drop the ring supply.
- Fault-path reset window: between the fault and the reset the outputs are driven low in a handful of instructions; the ring data lines (PC6/PC7) are not touched.
- [ ] Target fault injection: `Error_Handler` and a HardFault during a SET pulse (scope on PC4/PC5); HIL: reset or brownout while LOCKED, IWDG starvation with the reset cause reported, 500 kbit/s interop with the rt-core H743 at a ±0.5 % clock offset. T26.
