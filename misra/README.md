# MISRA C:2012 deviation register

CI runs the cppcheck MISRA addon over the target code (`src/`, without the host-only `hal/host`, plus the hand-written `cubemx/User/`) and **fails on any finding not listed here**. File- and project-scoped deviations are in `suppressions.txt`; single-line ones are inline `// cppcheck-suppress <rule> ; DEV-xxx: <reason>` comments, and CI rejects any inline suppression without a `DEV-` number. Register, list and comments change together, in the same PR, with a reason.

| ID | Rule (category) | Scope | Reason | Compensating measure |
|---|---|---|---|---|
| DEV-001 | 15.5 single point of exit (advisory) | project | Early returns for argument and state checks keep the code flat and readable; a single exit would need flag variables and deeper nesting. | Early returns are argument/state guards; every return path is exercised by the host tests (coverage floors in CI); `-Wall -Wextra -Werror` plus cppcheck warning checks are blocking. |
| DEV-002 | 8.7 no external linkage if used in one unit (advisory) | `app/safety_app.c` (`safety_app_init()`, `safety_app_step()`, `safety_app_status()`), `features/indicator/indicator.c` (`indicator_init()`, `indicator_step()`, `indicator_output()`: one inline suppression each, the blind-spot decision that will call them does not exist yet; D-075 item 4, D-082) | The application entry points are called by the board `main()` (red zone, with the CubeMX project, D-118) and the host tests, neither of which the addon scans. | Revisit when the board `main()` lands: drop the deviation for the app entry points; drop the indicator rows when the blind-spot feature (through `app/`) calls them. |
| DEV-003 | retired by D-118 | none | Was the `union` in the H755 mailbox region type (19.2); the mailbox is gone with the platform-CAN link. The number is not reused. | none |
| DEV-004 | 8.7 (advisory), 11.6 (required), 21.2 (required) | `cubemx/User/sbrk_fail.c` (`_sbrk`) | `_sbrk` is the newlib hook the C library calls by that name (reserved identifier, external linkage because the linker resolves it from libc), and its failure value is the library's `(void *)-1` (an integer-to-pointer cast). The stub exists to make the heap fail (invariant 5). | It always returns failure and sets ENOMEM; CI `tools/check_image_heap.py` fails if any heap symbol, `_sbrk` included, is linked into the image. |
| DEV-005 | 1.2 language extensions (advisory), Dir 4.3 assembly isolated (required), 20.10 `#`/`##` (advisory) | `cubemx/User/boot_checks.h`, `cubemx/User/boot_checks.c`, `src/hal/fault_record.h` (naked fault handler entry asm, `always_inline`, `noreturn`, `used`, `section` attributes; 20.10 `#`/`##` for the asm tag literal, inline suppressions) | The fault path must not push onto a possibly corrupt stack: it needs a naked handler, a `msr MSP` reload and a branch, which only inline asm and compiler attributes can express; the `.noinit` records need a section attribute. | The asm is one macro (`BOOT_FAULT_ENTRY`) in one header; CI `tools/check_fault_handlers.py` checks the disassembly of every handler (MSP reload first, no push, no call). |
| DEV-006 | 11.4 (advisory), 8.7 (advisory), 2.5 (advisory), 12.2 (required), 17.3 (mandatory, tool false positive) | `cubemx/User/boot_checks.h`, `cubemx/User/boot_checks.c`, `src/hal/fault_record.h` (2.5). File-level (`suppressions.txt`): 8.7 and 2.5. Everything else is an inline `cppcheck-suppress` (single line or begin/end block) at the exact lines | 11.4: register access through the CMSIS peripheral macros (`RCC->...`, integer-to-pointer casts inside the vendor headers). 8.7 and 2.5: the entry points, macros and fault tags are used by the generated `Src/main.c` and `Src/stm32g4xx_it.c` and by the host tests, which this scan does not read (same as DEV-002). 12.2: `mask << pos` inside `_Static_assert` against CMSIS macros, all operands constants in 32-bit range (the assertion itself proves the value). 17.3: the CMSIS intrinsic `__NOP()` expands to inline asm, which the addon reports as an implicit declaration. | Hand-written files only; the CMSIS headers are not scanned (`--suppress=*:*cubemx/Drivers/*`); register values are asserted at compile time against the vendor masks. |

CI builds cppcheck 2.22.0 and caches it. Before the MISRA step it checks that the addon reports 10.8, 15.6 and 17.7 on `misra/canary.c`, so a missing or broken addon never passes as a clean run.

**Generated code:** `external/vehicle-defs/gen/c/safety/` is excluded here (`--suppress=*:*external/*`). It is MISRA-checked, blocking, in vehicle-defs CI (its own register in `misra/README.md` there).

**Local runs (macOS):** Homebrew's python3 may lack `expat`; add `--addon-python=/usr/bin/python3` locally (never in `ci.yml`).
